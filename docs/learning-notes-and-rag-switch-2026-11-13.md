# 学习笔记与 RAG 部署开关

## 使用流程

1. 在 AI 问答中等待回答完成，选择「存为学习笔记」。默认选中本轮问题和回答，也可选择其他相关问答。
2. 编辑标题、困惑、正文和学习状态。可直接保存原文，也可选择「AI 整理」生成可编辑草稿；整理失败不会清空编辑内容。
3. 从「学习笔记」按关键词和状态查找，打开后编辑、查看原始问答，或选择「继续问」。
4. 关联会话每轮读取最新笔记。回答后选择「更新这条笔记」，编辑确认后保存，新增问答追加到原始快照。

状态为「待弄懂」「待复习」「已理解」，由本人选择，不通过一次答题自动判断。笔记支持普通文本搜索；本版不包含笔记向量化、根据笔记出题或自动安排复习。

新回答的持久化 ID 随 SSE 完成事件返回，保存来源按 ID 匹配，不按相同文字猜测。未完成、失败及停止的回答不作为可选笔记来源。原始快照独立保存，删除来源会话不会删除笔记；删除笔记解除会话关联，仍可继续普通聊天。

## RAG 开关

部署配置 `jobai.rag.enabled` 默认 `false`，改变后重启后端、刷新已打开的前端页面。

```yaml
jobai:
  rag:
    enabled: false
```

也可以在启动命令后添加 `--jobai.rag.enabled=true`，或使用 Spring 环境变量 `JOBAI_RAG_ENABLED=true`。无密钥部署模板 `application-template.yml` 和生产配置另外支持 `RAG_ENABLED`，默认关闭。

关闭时：

- 不构造 Elasticsearch 客户端、embedding 模型和知识库检索组件；无需 ES 运行或填写向量模型凭据。
- 聊天直接调用模型；笔记上下文直接传入，不经过 ES。
- 隐藏知识库、ES 管理、检索配置和刷题知识库选择，相关后端接口返回 503「知识库检索未启用」。权限验证仍生效。
- 普通出题接收空 `kbIds` 和出题方向；有历史薄弱点时可以沿用薄弱点方向。
- MySQL、Redis 和聊天模型仍然需要配置和运行。简历、面试、答题和错题功能保留。

开启时恢复原知识库管理、导入、检索和知识库出题能力，保留原有数据库及 ES 数据。开关为部署级配置，不是页面上的即时切换按钮。

`ai-rag-agent/knowledge/src/main/resources/migrations/20261113_learning_notes.sql`

随后执行 `ai-rag-agent/knowledge/src/main/resources/migrations/20261113_learning_notes_integrity.sql`，补充笔记版本和保存请求唯一约束。已有笔记初始版本为 0；新版前后端应配套部署。此次修复与验证见 [学习笔记六项修复](learning-note-fixes-2026-11-13.md)。

后续曾增加 `20261113_learning_note_source_ranges.sql`。现在已采用[独立来源与自由正文的操作模型](project-model-and-note-operations.md)，不再依赖来源位置；旧列保留但不读写，新流程无需执行该位置迁移，也不需要改写已有笔记。

迁移可重复执行，新增 `learning_note` 表及 `chat_session.note_id`，不删除原数据。新安装使用更新后的 `schema.sql`。笔记包含用户归属、可编辑正文、状态和来源快照，所有接口及来源消息均检查归属。

列表使用显式计数与分页 SQL，避免依赖当前项目未配置的 MyBatis 分页插件。
