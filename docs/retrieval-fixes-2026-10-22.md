# 检索修复及真实效果验证（2026-10-22）

已修复此前确认的五项问题：相关性判断无效、最低分未应用、候选过早截断、追问改写缺少历史、来源元数据丢失及融合分数被误标为相关度。

## 当前行为

1. 聊天取最近最多 6 条 user/assistant 历史供问题改写使用，单条最多 1000 字符，总计不超过 4000 字符；不传 system/tool 消息或额外元数据。重排与相关性判定使用改写后的明确问题。
2. 候选数量独立于最终返回数量：取 `max(10, 动态 topK, 最终数量 × 2)`，上限 50。聊天最终仍最多返回 5 条，重排失败也遵守最终数量限制。重排响应的重复、越界和空索引会被忽略。
3. `minScore` 传给 ES kNN 的 `similarity`，语义为余弦相似度；返回后以 `2 × _score - 1` 再次核对。BM25 采用独立计分尺度，不使用向量阈值过滤。
4. 原问题和改写问题的召回结果融合后，进行一次批量 LLM 相关性判断。每个候选必须有唯一编号及布尔结论，有效的 false 会过滤对应片段；全为 false 时返回未找到内容。无效/不完整响应、模型不可用或调用失败时保留候选并记录降级日志，避免把服务故障误判成无资料。
5. 从 ES 保留标题路径、知识库 ID、文档 ID、片段 ID；RRF 按片段 ID 去重，兼容旧调用时按来源与内容组合去重。不同来源的同文片段不再被无条件合并。最终提示词保留来源，不再把 RRF 排名分数展示成“相关度”或可信度。

主要修改：`VectorRetrievalService.java`、`ElasticsearchEmbeddingStoreAdapter.java`、`KnowledgeRetrievalTool.java`、`StreamingChatService.java`，以及四个新增测试类。刷题复用的底层混合检索同步获得阈值、元数据和相关性过滤修复；未另行把聊天改写和重排接到刷题流程。
