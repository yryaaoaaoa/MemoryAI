# 学习笔记知识树：存储与升级

## 页面使用

聊天页默认开启“自动整理”，右侧学习树展示知识点和所选节点的笔记，可折叠并收起整个面板。每轮回答完整保存后自动整理；不要求先选问答、填写标题或保存表单。开关按当前用户在本机保存，关闭只影响之后发送的问答，已经提交的整理继续完成。

点击节点只浏览；点击“从这里继续问”才为下一轮请求设置 `noteNodeId`，输入框上方可以取消。后台刷新保留正在浏览的节点与折叠状态。每条回答的“手动整理”和树底部的“编辑”保留原编辑流程；版本冲突不覆盖用户草稿。

学习笔记详情和聊天中的手动编辑共用树编辑器。旧 Markdown 笔记选择“转为知识树”后，原正文完整放入“原笔记”节点；点击保存才写入数据库，取消编辑可恢复转换前的内容。旧笔记关联会话首次自动更新时，同样完整保留原正文为“原笔记”节点。

节点标题和 Markdown 正文可直接编辑，支持添加子节点/同级节点、上下移动、缩进/提升、折叠、搜索、全文阅读和 Markdown 导出。删除分支可以撤销。保存使用现有版本号校验，失败时保留当前草稿。搜索结果开始编辑时退出搜索并展开祖先，避免修改关键词后编辑框消失。

手动编辑中复制问答会新增“补充问答”根节点；编辑器里的 AI 整理结果仍新增为独立根节点供用户对照。“将所选原文填入正文”会明确提示将整棵树替换为一个原文节点。原始问答快照始终独立保存。

## 自动整理

`RagController` 在流式回答任务完成后调用 `LearningTreeService`。仅 `response_status=completed` 的已落库回答可整理；停止、失败、截断回答不会入树。现有 `taskExecutor` 处理整理，同会话按顺序执行，聊天显示不等待整理。

每轮一次模型调用：读取现有树、最近四轮范围内的问答、本轮原文及可选追问节点，返回 `add / update / none` 中一个局部操作。补充解释更新原节点，深入的问题放入子节点，旧话题回到原分支，独立话题添加根节点，确认或寒暄可跳过。节点 ID 由程序生成；模型不能删除、搬移或重写其他分支，更新节点保留原子节点。模型输出在保存入口执行现有树结构和长度校验。

第一版直接传入现有树正文（笔记沿用 40000 字上限），避免增加选支模型、检索服务或额外 Agent。明确从节点追问时，聊天上下文使用该节点正文；普通追问保留已有笔记背景和聊天上下文行为。

首次有效整理创建笔记并设置已有 `chat_session.note_id`，之后更新同一笔记；从笔记继续问的会话沿用原笔记。保存树、追加本轮独立问答快照、关联会话和标记本轮完成在同一个数据库事务里提交。模型调用在事务外，保存使用原有版本号；遇到手动修改或其他关联会话的版本冲突，保留现有内容并允许重试。

处理记录使用原有 `chat_message.metadata` 的 `note_status`、`note_node_id`、`note_id`、`note_context_node_id`、`note_error`。完成记录独立于来源快照，因此重复读取、刷新或重试不会再次插入已完成轮次；`none` 也记录完成，不创建空笔记。

- `GET /api/sessions/{id}/learning-tree` 返回 `{note,status,nodeId,messageId,error}`，状态为 `idle/pending/updated/unchanged/failed`。有未完成轮次时先显示最早一轮的状态，否则返回最新记录。`note` 沿用现有笔记字段。
- `POST /api/sessions/{id}/learning-tree/retry` 重新排入未完成轮次，已完成轮次跳过。整理失败时后续轮次保留待处理；明确重试或下次完成回答时从未完成处继续。
- 流式请求增加 `organizeNotes: boolean`，旧调用方省略时关闭；聊天页默认显式传 `true`。`noteNodeId` 为当前会话笔记中的节点 ID，不接受其他笔记节点。

前端在回答完成后读取状态，等待对应消息的结果；切会话和离开页面停止轮询，后台任务继续。服务重启留下的待处理记录显示可重试，不在读取接口隐式调用模型。全程不新增数据库表、迁移、消息中间件或模型依赖。

## 接口合同

现有 `/api/learning-notes` 创建、详情、列表和更新接口增加可选 `treeJson` 字符串。原始问答快照、来源会话、学习状态、权限和版本规则保持原有行为。

```json
{"version":1,"nodes":[{"id":"stable-node-id","title":"知识点","body":"Markdown 解释","children":[]}]}
```

树在保存入口解析为节点结构并校验：节点编号全树唯一且最长 128 字符，标题非空、单行、最长 120 字，正文是字符串，子节点是数组；整棵树至少有一个节点，最多 1000 个节点和 32 层。树 JSON 最长 300000 字符，生成的 Markdown 正文沿用 40000 字符上限。

提交树时，以树为准生成 `content`，忽略请求中的旧正文：根节点使用二级标题，子节点依次加深，超过六级使用加粗标题。正文内容、代码块和表格按原样保留。树与生成正文在同一条带版本条件的 SQL 中保存，正文继续用于搜索和“继续问”上下文。新增树的创建重试身份包含规范化后的树数据，旧纯文本请求的重试身份不变。

旧笔记的 `treeJson` 为 `null`，读取时不会转换或重写。旧客户端更新时，省略树或传 `null`，若正文未变则保留已有树；正文改变则清空树，避免树与正文不一致。要修改树结构应显式提交 `treeJson`。节点折叠、选择状态属于界面状态，不存进笔记内容。

## 数据库升级

新库使用 `ai-rag-agent/knowledge/src/main/resources/schema.sql`。已有库先执行：

```text
ai-rag-agent/knowledge/src/main/resources/migrations/20261116_learning_note_tree.sql
```

该 SQL 为 `learning_note` 添加可空 `tree_json JSON` 列，可重复执行，不更新既有笔记行。GitHub Actions 发布包包含此文件，`deploy/docker/deploy.sh` 在构建成功后、替换后端前执行。迁移失败时不替换运行中的应用；应用健康检查失败可回滚旧版，新增列保留。手动部署需先执行同一 SQL。
