# 学习笔记知识树：存储与升级

## 页面使用

聊天页默认开启“自动整理”，右侧是只显示问题标题的目录，可折叠并收起整个面板。每轮回答完整保存后自动确定问题标题和归属，不再生成节点摘要；不要求先选问答、填写标题或保存表单。开关按当前用户在本机保存，关闭只影响之后发送的问答，已经提交的整理继续完成。

点击节点，在聊天主区回看它关联的原始问答，侧栏下方显示至多三个还没聊过的推荐问题。点击推荐立即以原问题文本发问，并携带该节点 `noteNodeId`；“自己提问”只设置下一轮的讨论起点。浏览节点不隐式改变手动输入的上下文。原问答回看可随时返回最新聊天；新问题发送后自动返回聊天。输入框已有草稿或正在回答时，推荐按钮禁用，避免覆盖草稿或重复发送。

后台刷新保留所选节点与折叠状态。学习笔记入口 `/notes` 只提供学习记录的搜索、打开和删除；点击记录经 `/notes/:id` 打开对应的聊天与问题目录。列表“开始新话题”显式创建新会话，不恢复上次会话。聊天与笔记共用同一个问题目录和原问答、推荐界面。

2026-11-17 已撤下手工保存、正文编辑、树编辑器、学习状态筛选和 AI 整理表单，删除对应的前端组件及无用的编辑离开保护。旧笔记正文、困惑、原状态和来源快照通过聊天页“历史笔记”只读查看；新自动节点全部为空正文时不显示该入口。旧节点无法关联原问答时明确说明，并提供历史笔记入口，不把摘要当原文。

`POST /api/learning-notes/{id}/open` 校验笔记归属后，返回该用户与该笔记关联的最近更新会话（同时间按 ID 倒序）；没有关联会话时才创建一个。打开和重复访问不调用模型、不改写笔记；来源会话删除后仍可打开已有快照。删除学习记录会删除该笔记的快照和树，并解除现有会话关联，保留聊天消息。

数据库字段及旧 CRUD、draft、创建关联会话接口暂保留兼容，生产前端已不调用手工保存和整理接口。旧笔记关联会话首次自动更新时，原正文完整保留为“原笔记”节点；新问答正常追加。独立离线树原型不接入生产路由。

## 自动整理

`RagController` 在流式回答任务完成后调用 `LearningTreeService`。仅 `response_status=completed` 的已落库回答可整理；停止、失败、截断回答不会入树。现有 `taskExecutor` 处理整理，同会话按顺序执行，聊天显示不等待整理。

每轮一次归类调用：读取树的标题与层级、最近四轮范围内的问答、本轮原文及可选追问节点，返回 `add / update / none` 中一个局部操作。新的具体问题增加节点，深入追问挂在相关问题下；对同一个问题的重复澄清关联原节点，确认或寒暄可跳过。模型只输出标题与归属，不输出正文。程序生成节点 ID，记录本轮问题和回答的消息 ID；更新节点保留原正文和子节点，不改写其他分支。

新自动节点 `body` 为空，`sourceMessageIds` 指向笔记内独立保存的原始问答快照。明确从节点追问时，聊天上下文使用该节点标题及原问答，保留代码、例子与原有条件。普通追问保留已有笔记背景和聊天上下文行为。

推荐在选中节点时通过现有模型服务按需生成。输入包括所选问题、它的原问答、问题目录，以及已保存和当前会话中提问过的内容；模型判断尚未讲过的方向，程序再过滤忽略空白、标点和英文大小写后完全重复的问题。语义去重依赖模型，不保证不同说法的重复绝不会出现。前端按会话、笔记版本、节点和聊天轮次缓存，发送新问题即清空缓存；推荐失败可以单独重试，不影响原文回看。没有新增 Agent、向量检索或推荐数据表。

首次有效整理创建笔记并设置已有 `chat_session.note_id`，之后更新同一笔记；从笔记继续问的会话沿用原笔记。保存树、追加本轮独立问答快照、关联会话和标记本轮完成在同一个数据库事务里提交。模型调用在事务外，保存使用原有版本号；遇到手动修改或其他关联会话的版本冲突，保留现有内容并允许重试。

处理记录使用原有 `chat_message.metadata` 的 `note_status`、`note_node_id`、`note_id`、`note_context_node_id`、`note_error`。完成记录独立于来源快照，因此重复读取、刷新或重试不会再次插入已完成轮次；`none` 也记录完成，不创建空笔记。

- `GET /api/sessions/{id}/learning-tree` 返回 `{note,status,nodeId,messageId,error}`，状态为 `idle/pending/updated/unchanged/failed`。有未完成轮次时先显示最早一轮的状态，否则返回最新记录。`note` 沿用现有笔记字段。
- `POST /api/sessions/{id}/learning-tree/retry` 重新排入未完成轮次，已完成轮次跳过。整理失败时后续轮次保留待处理；明确重试或下次完成回答时从未完成处继续。
- `GET /api/sessions/{id}/learning-tree/nodes/{nodeId}` 返回 `{nodeId,title,messages}`。只从当前用户所属笔记的来源快照取原文；新节点在来源会话删除后仍可回看。旧自动节点可根据仍存在的消息关联恢复；无法可靠对应的旧节点返回空列表，界面说明未关联，不拿摘要代替原文。
- `POST /api/sessions/{id}/learning-tree/nodes/{nodeId}/suggestions` 返回 `{questions:[...]}`，不写笔记，失败不隐藏原问答。
- 流式请求增加 `organizeNotes: boolean`，旧调用方省略时关闭；聊天页默认显式传 `true`。`noteNodeId` 为当前会话笔记中的节点 ID，不接受其他笔记节点。

前端在回答完成后读取状态，等待对应消息的结果；切会话和离开页面停止轮询，后台任务继续。服务重启留下的待处理记录显示可重试，不在读取接口隐式调用模型。全程不新增数据库表、迁移、消息中间件或模型依赖。

## 接口合同

现有 `/api/learning-notes` 创建、详情、列表和更新接口增加可选 `treeJson` 字符串。原始问答快照、来源会话、学习状态、权限和版本规则保持原有行为。

```json
{"version":1,"nodes":[{"id":"stable-node-id","title":"Token 怎么变成向量？","body":"","children":[],"sourceMessageIds":[1,2]}]}
```

树在保存入口解析为节点结构并校验：节点编号全树唯一且最长 128 字符，标题非空、单行、最长 120 字，正文是字符串，子节点是数组；整棵树至少有一个节点，最多 1000 个节点和 32 层。树 JSON 最长 300000 字符，生成的 Markdown 正文沿用 40000 字符上限。

`sourceMessageIds` 是可选的正整数、无重复数组；原有节点不要求补写。手动编辑、移动和保存保留此字段。读取原文时只取编号与该笔记来源快照的交集，不能通过伪造编号读取其他聊天。新旧格式共用现有 JSON 列，无数据库迁移。

提交树时，以树为准生成 `content`，忽略请求中的旧正文：根节点使用二级标题，子节点依次加深，超过六级使用加粗标题。正文内容、代码块和表格按原样保留。树与生成正文在同一条带版本条件的 SQL 中保存，正文继续用于搜索和“继续问”上下文。新增树的创建重试身份包含规范化后的树数据，旧纯文本请求的重试身份不变。

旧笔记的 `treeJson` 为 `null`，读取时不会转换或重写。旧客户端更新时，省略树或传 `null`，若正文未变则保留已有树；正文改变则清空树，避免树与正文不一致。要修改树结构应显式提交 `treeJson`。节点折叠、选择状态属于界面状态，不存进笔记内容。

## 数据库升级

新库使用 `ai-rag-agent/knowledge/src/main/resources/schema.sql`。已有库先执行：

```text
ai-rag-agent/knowledge/src/main/resources/migrations/20261116_learning_note_tree.sql
```

该 SQL 为 `learning_note` 添加可空 `tree_json JSON` 列，可重复执行，不更新既有笔记行。GitHub Actions 发布包包含此文件，`deploy/docker/deploy.sh` 在构建成功后、替换后端前执行。迁移失败时不替换运行中的应用；应用健康检查失败可回滚旧版，新增列保留。手动部署需先执行同一 SQL。
