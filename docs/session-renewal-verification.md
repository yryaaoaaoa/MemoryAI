# 登录会话续期与验证

2026-11-13。本项目使用 Cookie + Redis Spring Session，没有 JWT/refresh token。本轮沿用现有登录方式补齐浏览器 Cookie 续期。

## 当前行为

- 有效登录请求经过安全链后，在响应提交前重发同一个会话 Cookie；有效期取当前 Session 的实际空闲时限，本机为 1800 秒。Redis 原有的访问时间更新保持不变。
- 复用框架的 CookieSerializer，保留 Cookie 名称、路径、域、HttpOnly、Secure、SameSite 配置。过滤器只注册到安全链一次；SSE 也能在响应头提交前续期。
- 登录继续轮换会话 ID，退出继续销毁 Session 并清除 Cookie。续期过滤器跳过登录、注册、退出；不会为匿名请求创建登录态，也不会复活过期会话。
- 续期由接口请求触发。只在本地阅读或编辑、不发请求超过 30 分钟，仍需重新登录；没有后台心跳维持永久登录。
- 普通请求和 SSE 的 401 统一处理，并发过期响应共用一次离开确认。首次访问未登录由路由引导登录，不显示“登录已过期”；密码错误显示具体错误。退出时已经过期，视为已退出。
- 有未保存笔记时，等失败操作结束忙碌状态后再确认离开。选择“继续编辑”保留当前草稿，并提供新标签页登录入口；使用原账号重新登录后，回原页手动重试。选择“放弃修改”才跳转登录；不会额外触发一次页面卸载确认。
- 不自动重发保存、出题、面试或聊天等请求。恢复后的成功请求会关闭过期通知。草稿保留在当前页面内存中，不代表刷新或关闭标签页后仍能恢复。
