# 学习笔记六项修复与验证

本文保留历次修复记录。当前实现已按[项目对象关系与笔记操作规则](project-model-and-note-operations.md)收敛：原始问答独立保存，正文自由编辑；下文历史上的字符位置跟踪和原文自动判重已退出业务逻辑。

## 修复结果

1. **旧页面覆盖新笔记**：聊天打开“更新这条笔记”时重新读取最新内容；所有更新携带 `expectedVersion`，数据库执行带版本条件的原子更新。版本已变化时返回 HTTP 409，保留编辑内容；可以在新标签查看最新笔记，或确认后载入最新版本再编辑。
2. **AI 整理丢失当前编辑**：请求携带当前标题、困惑和正文 `currentDraft`；后端将其与所选问答一起交给模型。失败保留原表单，整理成功只更新草稿，不自动保存。
3. **后退或切换页面丢失草稿**：抽屉关闭、路由切换、浏览器后退及聊天内切换会话使用离开检查。取消离开保留内容；保存和整理期间阻止离开。浏览器刷新/关闭使用原生未保存提示。
4. **退出登录先注销、再询问草稿**：注销请求前检查未保存内容；取消时不注销。确认退出且接口成功后导航只放行本次跳转；退出失败保留会话与草稿，后续离开检查仍有效。
5. **多选问答只更新来源、不更新正文**：未手动编辑的原文正文跟随勾选自动更新；手动编辑或 AI 整理后保留正文，提示通过 AI 合并或明确选择“将所选原文填入正文”。替换手动正文需确认。
6. **保存响应丢失后重试生成重复笔记**：编辑器打开时生成稳定 UUID `requestId`；数据库按用户及请求编号建立唯一约束。相同请求和内容重试返回已保存笔记；请求编号相同但内容不同则返回 409，引导先查看已保存笔记，保留当前编辑。

## 来源位置持久化与撤销恢复

后续审查确认：原文后增加手写尾注，在重开、AI 合并及冲突载入后会丢失来源编号；手动修改答案后 Ctrl+Z 恢复正文，也不会恢复编号。此次修复改为保存可校验的来源位置，而不是仅在打开时从正文推测。

- `learning_note.source_ranges` 保存消息 ID 和 UTF-16 正文起止位置，后端核对范围所属快照、唯一编号、上下界和精确原文。新增迁移 `20261113_learning_note_source_ranges.sql`；旧记录为 NULL，不猜测回填，旧版笔记仍只识别能确认的完整问答。显式空数组表示已确认没有有效范围。
- 新建和更新笔记都保存范围，详情编辑与更新抽屉一致。追加后取消勾选，只提交已保存快照及当前所选来源允许的范围；重新勾选仍保留本地身份，不会重复追加。
- 重开和冲突载入采用服务器范围，冲突载入清空旧草稿的位置历史。AI 保留原正文或已有完整问答组时保留可信位置；真正改写原文时使相应位置失效。不同问题的相同短答案仍不会互相冒认。
- 编辑器记录正文与来源编号的对应状态；撤销恢复正文时恢复相应编号。连续输入的逐字历史有容量限制，另保留来源编号增减前的有界检查点，避免输入长段文字后撤销回原文时丢失身份。
- 兼容旧客户端省略范围：完整旧正文仍在时整体平移；无法确认时清除位置。创建请求的既有 hash 不改变，保留旧重试回执兼容性。
